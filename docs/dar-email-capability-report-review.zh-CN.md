## 3. 风险与公开仓库注意点

### 3.1 公开仓暴露

1. community-ops-kit 为公开仓。PR #1 的分支与提交已公开可见；即使不合并，在分支删除前内容仍可被查看；合并进 main 后，撤回需改写历史。
2. 现稿含以下业务专属信息，公开后可被外部读取：
   - 付费分层叫法与分档依据；
   - 对照组比例与 UTM 命名规则；
   - 具体 Discord 频道名与 Max 身份组分配机制；
   - 高价值用户内容类型的画像描述；
   - 黑五先开与复盘的曾记日期。
3. 仓库 CONTRIBUTING 要求「平台专属的角色、频道、奖励、政策、权限不进入可复用核心」。现稿位于 `docs/`，不在 `skills/` 核心内，但仓库定位是通用社区运营工具包，单一业务方案放入公开仓与仓库定位不符。
4. `scripts/validate.rb` 只拦截私有项目名、令牌、webhook 等固定模式，不识别业务敏感措辞。校验通过不代表适合公开。
5. 粘贴稿含内部文档链接与本地路径。现稿与本回执均未写入，后续修订时需保持不写入。
6. 本回执第 1 节为确认口径，复述了现稿的部分业务口径，同样位于公开仓，去留随 PR #1 一并由 Owner 决定。
